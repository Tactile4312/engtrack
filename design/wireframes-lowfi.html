How people move through the system

The main path from sign-in to a deadline alert, followed by the five everyday tasks.

Create a project

  1. Tracker → + Add Project
  2. Fill project info, tick scopes, set dates
  3. Set engineer and due date per scope
  4. Save → project number checked → Project Details opens

Assign an engineer

  1. Project Details → scope row → ⋯ Edit
  2. Pick engineer → Save
  3. Engineer gets an in-app notice; change logged in history

Update progress (engineer, on phone)

  1. Notification or Projects → open project
  2. Tap own scope card → Update progress
  3. Set % and status, add note or photo
  4. Project progress recalculates; dashboard updates

Receive a deadline reminder

  1. Server checks deadlines every day, even with nobody logged in
  2. Sends 7 / 3 / 1-day, due-today or overdue alert (never twice)
  3. Bell count rises; optional browser or email alert
  4. Tap → project opens → alert marked read

Complete a project

  1. All scopes reach 100% / Completed
  2. PM sets project status to Completed
  3. Actual completion date recorded; reminders stop
  4. Project moves to Completed reports; archive later if wanted

Points to confirm

These decisions shape the next stage. A proposed answer is given for each. Please confirm or correct.

Q1 · Engineering scope list

Are these the nine scope types, with these names?

LiftingTransportJacking & SkiddingShutdownBridgingGBP CalculationRoute SurveyMS StudyDWG

Proposed: administrators can add or rename scopes later.

Q2 · How overall progress is calculated

A project's progress needs one consistent rule.

Proposed: simple average of its scopes (example above: 100, 60, 50, 20 → 58%). Alternatives: weight by scope duration, or let the PM override with a reason.

Q3 · Project number format

Do you have an existing numbering scheme to keep?

Proposed: CRM-YYYY-NNNN, generated automatically and editable for imported projects. Duplicates are always blocked.

Q4 · Who receives reminders

Reminder steps are 7, 3 and 1 day before, on the day, and overdue.

Proposed: the assigned engineer gets every step; the project manager gets 1-day, due-today and overdue; the salesperson only gets overdue. Email depends on a company mail account.

Q5 · Statuses

New Request, For Review, In Progress, On Hold, Waiting for Client, Waiting for Engineering, Completed, Cancelled.

Proposed: use these for both projects and scopes. Is anything missing from your current workflow?

Q6 · Milestones

Shown as examples: Request Received, Engineering Review, Scope Confirmation, Calculation Completed, Drawing Completed, Client Approval, Project Completion.

Proposed: a default milestone set added to each new project, editable per project. Please share your real steps.

Q7 · Who can see what

Roles: Administrator, Project Manager, Engineer, Salesperson.

Proposed: engineers see projects they are assigned to; salespeople see their own clients' projects; PMs and admins see all.

Q8 · Existing data

Is there a current tracking sheet to import at launch?

Proposed: a one-time import from Excel or CSV, if you can share the file layout.
